# 오마고치 백엔드 개발 요약 - 2026-08-08

## 작업 개요

오늘 작업은 기존 Spring Boot 백엔드 구조를 유지하면서 프로필/닉네임, 커뮤니티, WebSocket/STOMP, Redis 기수 Presence를 단계별로 구현한 것이다. 프론트엔드, 친구/차단, 채팅, 펫/진화, Presence 공개 범위 기능은 구현하지 않았다.

## 프로필 / 닉네임

- API
  - `GET /api/users/me/profile`
  - `PATCH /api/users/me/nickname`
- 닉네임 정책
  - `user_characters.nickname` 재사용
  - 앞뒤 공백 제거 후 길이 2~12 검증
  - 현재 존재하지 않는 문자셋, 비속어, 중복 검증 규칙은 추가하지 않음
- 프로필 집계
  - 완료된 유효 학습 기록만 집계
  - 출석 날짜는 중복 제거된 날짜 기준
  - 출석 streak는 오늘 또는 어제부터 역방향 계산
  - 누락된 숫자 값은 0 반환
- 기존 도메인/데이터 재사용
  - User/Profile/UserSettings 엔티티나 테이블을 만들지 않음
  - 대표/current `UserCharacter` 정책 재사용
  - `game_characters`에 없는 `type`, `assetKey`는 null 값으로 반환

## 커뮤니티

### 읽기

- 게시글 스키마
  - Flyway `V17__create_community_posts.sql`
  - `community_posts`는 `NOTICE` / `FREE`, `GLOBAL` / `COHORT`, 고정 여부, soft delete 상태를 저장
- GLOBAL/COHORT 공개 범위
  - GLOBAL 게시글은 인증 사용자에게 노출
  - COHORT 게시글은 해당 기수의 ACTIVE membership이 있을 때만 노출
  - 공개 범위는 DB query 조건에서 처리하고 메모리 필터링을 하지 않음
- JPA/JPQL 필터링, 검색, 페이징, 정렬
  - JPA query layer에서 타입 필터, 제목/내용 검색, 페이징, count 처리
  - 기본 정렬은 `pinned DESC`, `created_at DESC`, `id DESC`

### 쓰기 / 권한

- 생성/수정/삭제/고정
  - `POST /api/community/posts`
  - `PATCH /api/community/posts/{postId}`
  - `DELETE /api/community/posts/{postId}`
  - `PATCH /api/community/posts/{postId}/pin`
- STUDENT / MENTOR / MANAGER / SYSTEM_ADMIN 정책
  - STUDENT는 FREE 게시글 작성 가능
  - MENTOR, MANAGER는 ACTIVE membership이 있는 기수에 COHORT NOTICE 작성 가능
  - SYSTEM_ADMIN은 GLOBAL NOTICE와 모든 기수 NOTICE 작성 가능
  - 고정/고정 해제는 SYSTEM_ADMIN 전용
- 서버 측 membership 검증
  - 요청 본문의 `userId`, `authorUserId`, `role`, 관리자 플래그를 신뢰하지 않음
  - JWT 사용자와 기수 membership을 서버에서 확인
- soft delete
  - 삭제는 게시글 soft delete 정책으로 처리

### 첨부파일

- 첨부파일 메타데이터
  - Flyway `V18__create_community_post_attachments.sql`
  - DB에는 storage key, 원본 파일명, content type, 크기, 표시 순서 등 메타데이터만 저장
  - 바이너리 파일 내용은 DB에 저장하지 않음
- 로컬 파일시스템 저장소 추상화
  - `CommunityAttachmentStorage` 인터페이스와 `LocalCommunityAttachmentStorage` 구현
  - 추후 S3 등으로 교체할 수 있게 커뮤니티 도메인과 분리
- 설정 가능한 저장 루트
  - `community.attachments.storage-root`
  - 기본값 `data/community-attachments`
- 제한/허용 형식
  - 최대 5개 파일
  - 파일당 5MB
  - `jpg`, `jpeg`, `png`, `gif`
  - 실제 파일 header 기반 MIME: `image/jpeg`, `image/png`, `image/gif`
- 안전한 서버 생성 storage key
  - 클라이언트 파일명을 저장 경로로 사용하지 않음
  - 서버 측 UUID 기반 storage key 생성
  - 경로 탈출, 안전하지 않은 파일명, 확장자/MIME 불일치, 빈 파일 검증
- 정리 동작
  - 파일 저장 후 메타데이터 저장이 실패하면 새로 저장된 파일을 정리
  - 게시글 삭제 시 첨부파일 메타데이터와 저장 파일을 함께 정리

## WebSocket / STOMP

- `spring-boot-starter-websocket` 추가
- 엔드포인트: `/ws`
- STOMP destination 규칙
  - `/app/presence/heartbeat`
  - `/topic/cohorts/{cohortId}/presence`
  - `/user/queue/notifications`
- CONNECT JWT 인증
  - STOMP `Authorization: Bearer ...` header를 기존 `JwtDecoder`와 `JwtAuthenticationConverter`로 검증
- 인증된 Principal
  - 검증된 `JwtAuthenticationToken`을 WebSocket Principal로 설정
- SUBSCRIBE 권한
  - 인증된 Principal 없이는 구독 거부
  - 지원하지 않는 destination 구독 거부
- 기수 topic 권한
  - `/topic/cohorts/{cohortId}/presence`는 JWT 사용자에게 해당 기수 ACTIVE membership이 있을 때만 허용

## Redis Presence

- `spring-boot-starter-data-redis` 추가
- Redis key
  - `realtime:session:{sessionId}` -> `userId`, `cohortId`, TTL
  - `presence:user:{userId}:sessions` -> 활성 WebSocket session ID 목록
  - `presence:user:{userId}` -> `ONLINE` / `OFFLINE`
  - `presence:cohort:{cohortId}` -> 현재 온라인 사용자
- 60초 session TTL
  - `realtime.presence.session-ttl`
  - 환경 변수: `REALTIME_PRESENCE_SESSION_TTL`
- CONNECT 등록
  - JWT 사용자 기준으로 현재 ACTIVE 기수 membership을 서버에서 찾고 Redis session/user/cohort 상태를 등록
- heartbeat
  - `/app/presence/heartbeat`
  - 클라이언트 payload 없이 WebSocket session과 JWT 사용자 기준으로 TTL 갱신
- disconnect/만료 정리
  - disconnect event에서 해당 session 제거
  - snapshot 계산 시 만료된 session hash를 user session set에서 정리
- 다중 session 동작
  - 하나의 유효 session이라도 남아 있으면 사용자 ONLINE 유지
  - 마지막 유효 session 제거/만료 시 OFFLINE 처리 및 기수 온라인 set에서 제거
- ONLINE/OFFLINE
  - 이번 범위에서는 실제 전이 상태로 ONLINE/OFFLINE을 사용
  - `AWAY`, `BUSY`는 enum에만 준비되어 있고 별도 상태 전이는 구현하지 않음
- 기수 snapshot/broadcast
  - CONNECT, disconnect, cleanup 후 `/topic/cohorts/{cohortId}/presence`로 snapshot broadcast
  - 초기 snapshot은 `GET /api/cohorts/me/presence`
- Presence는 물리 출석이 아님
  - Presence는 Redis ephemeral WebSocket 상태이며 출석/학습 기록과 분리

## 프레임워크 / 라이브러리 사용

- Spring Security
  - REST와 WebSocket 모두 JWT 검증, `JwtAuthenticationToken`, role claim 변환 재사용
  - 사용자 식별은 서버 측 인증에서만 수행
- Bean Validation
  - request DTO 입력 검증에 사용
  - 닉네임, 커뮤니티 생성/수정 payload 검증은 기존 validation/error convention을 따름
- Spring Data JPA
  - 커뮤니티 게시글, 첨부파일 메타데이터, 기수 membership 조회에 사용
- QueryDSL
  - 기존 학습 프로필 요약 집계 repository에서 재사용
- Flyway
  - `community_posts`, `community_post_attachments` 스키마 추가에 사용
- MultipartFile
  - 이미지 첨부파일 upload 처리에 사용
  - raw multipart parsing은 직접 구현하지 않음
- Spring WebSocket/STOMP
  - endpoint, broker prefix, application destination, `ChannelInterceptor`, session disconnect event 사용
  - custom WebSocket protocol이나 raw frame parsing은 구현하지 않음
- Spring Data Redis
  - `StringRedisTemplate` hash/set/value/TTL 연산으로 ephemeral Presence 상태 저장
  - Redis `KEYS` 사용 없음
- Spring transaction/test support
  - application service transaction boundary 유지
  - focused unit/MVC/query/storage test로 단계별 검증

## 보안 결정

- 현재 사용자는 서버 측에서 식별
  - REST: `JwtAuthenticationToken` -> `AuthenticatedUser`
  - WebSocket: STOMP CONNECT JWT -> `JwtAuthenticationToken` Principal
- 클라이언트의 userId/role/admin flag를 신뢰하지 않음
  - 커뮤니티 작성자, 역할, 관리자 권한, WebSocket 사용자 식별은 request payload에서 받지 않음
- 기수 membership은 서버에서 확인
  - 커뮤니티 공개 범위/쓰기 권한
  - WebSocket 기수 topic 구독
  - Redis Presence 기수 결정
- WebSocket 구독 권한
  - `/topic/cohorts/{cohortId}/presence`는 ACTIVE membership 필요
  - 지원하지 않는 destination은 거부
- 첨부파일 경로/파일 안전성
  - generated storage key만 저장 경로로 사용
  - 경로 탈출 차단
  - 확장자와 실제 MIME/header 검증
  - 파일 개수, 파일 크기, 빈 파일 검증

## 현재 백엔드 흐름

HTTP:

```text
Controller
-> Application Service
-> Repository / Query adapter
-> DB
```

WebSocket CONNECT:

```text
STOMP CONNECT
-> JWT 인증
-> 인증된 Principal
-> ACTIVE 기수 확인
-> Redis Presence 등록
-> STOMP 기수 broadcast
```

WebSocket SUBSCRIBE:

```text
STOMP SUBSCRIBE
-> 인증된 Principal 확인
-> destination 규칙 확인
-> 기수 ACTIVE membership 권한 확인
-> 구독 허용/거부
```

Presence heartbeat:

```text
/app/presence/heartbeat
-> 인증된 WebSocket Principal
-> Redis session 조회
-> 기수 membership 재확인
-> session TTL 갱신
```
